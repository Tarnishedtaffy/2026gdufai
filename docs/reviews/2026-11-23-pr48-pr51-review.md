## 三、PR #51 审查

### 3.1 P1 · 契约声明“告警由 M2 账单写操作触发”，但 M2 写链路没有调用

**位置**

- `docs/contracts/module2-interface-v1.md:463`（本次 PR 新增）：
  > 本期不提供告警查询端点；告警由 `PUT` 与 M2 账单写操作触发，写入 `budget_alerts` 供后续通知模块消费。
- `backend/src/modules/budget/service.ts:285` `recalcBudgetForTransaction()`、`:311` `recalcBudgetsForMonth()`。

**证据**

```bash
git grep -n "recalcBudget" pr-51 -- backend/src
# 只命中 budget/index.ts 与 budget/service.ts，没有任何模块调用
```

M2 的写入路径（`backend/src/modules/ledger/intake.ts` 的 `insertTransaction`/`voidTransaction` 调用、`backend/src/modules/ledger/transaction-edit.ts` 的 `voidTransactionById`）均未 import 或调用预算模块；`backend/src/app.ts` 也只注册了路由，没有任何写后重算钩子。`backend/test/m4/alerts.test.ts:93` 等用例是**直接调用** `recalcBudgetForTransaction()`，因此测试通过并不能证明 M2 写入会触发告警。

**影响**

按当前实现，用户设置预算后正常记账，`budget_alerts` 不会新增记录；只有再次保存该预算时 `PUT` 才会补写已跨过的阈值。“超支提醒”在端到端流程里不可达，而契约第 463 行已经把它写成现行行为。

**建议（二选一）**

1. 按 PR 日志的 #38 计划，把 `recalcBudgetForTransaction()`/`recalcBudgetsForMonth()` 接到 M2 的入库、改账、作废写事务提交后，并补一条从 `POST /api/transactions/import`（或 `PATCH /api/transactions/:id`、`POST /api/transactions/:id/void`）到 `budget_alerts` 的集成测试；或
2. 本 PR 不动 M2，则把契约第 463 行改成“本期告警仅由 `PUT` 触发；M2 账单写操作在 #38 接入后生效”，并相应调整 PR 标题/描述里的“超支提醒”表述，避免契约与实现不一致。

### 3.2 P2 · 编辑态允许修改预算键（月份/scope/类别），PUT 只按键 upsert，可能写错月份或留下重复预算

**位置**

- `frontend/src/views/BudgetView.vue:16`（`editing`）、`:33-36`（`startEdit()`）、`:68`（月份 `@change="loadBudgets"`）
- `frontend/src/components/BudgetForm.vue:74-80`（提交时使用 `props.month`）、`:101-109`（编辑态回填 scope/category）、`:127-137`（scope/类别选择器在编辑态未禁用）、`:149-151`（`editing !== null` 时显示“保存修改”和“取消”）
- 契约 §2.8 与 `service.ts:231-261`：`PUT` 以 `(month, scope, categoryId)` 为幂等键，只做覆盖/新增，不迁移旧键。

**复现 A（切换月份）**

1. 进入预算页，月份为 `2026-11`，点击某个预算的“编辑”；
2. 不取消编辑，直接把月份切到 `2026-12`；
3. 表单仍显示 11 月预算的内容和“保存修改”；
4. 点击保存，请求体为 `{ month: "2026-12", ...旧预算字段 }`，会在 12 月新增/覆盖一条预算。

**复现 B（改 scope/类别）**

1. 编辑一条“月度总预算”，把类型改成“类别预算”并选一个类别后保存；
2. 请求的键变成 `(当前月, category, 该类别)`，后端按新键新建一条类别预算；
3. 原来的总预算不会被删除，页面上出现两条预算，但按钮文案是“保存修改”。

**原因**

`loadBudgets()` 只刷新列表，没有清空 `editing`；`BudgetForm` 的 `editing` watcher 只在 `props.editing` 引用变化时触发，月份变化不会触发。编辑态下 scope/类别选择器也未禁用，而 PUT 不支持“换键更新”。

**建议**

- 编辑态禁用月份、scope 和类别（只允许改金额与阈值），并在月份变化时清空 `editing`；或
- 如果确实要支持换键，提交时先 `DELETE` 原预算再 `PUT` 新键，并在 UI 上明确提示“将移动预算”。
- 最低限度的修复：月份变化时 `editing.value = null`，并对编辑态的 scope/类别变化禁用或二次确认。

### 3.3 P3 · mock 的已用金额没有排除中性记录，与契约统计口径不一致

**位置**

- `frontend/src/mock/budget.ts:21-30` `spentForMonth()`
- 契约 `docs/contracts/module2-interface-v1.md:345`：`spentCents` 只统计 `direction='expense'`、`entry_type='normal'`、`status='confirmed'`。

mock 当前只过滤 `direction` 和 `status`，没有检查 `entryType`。目前 `MOCK_TRANSACTIONS` 没有退款/还款中性记录，所以界面上暂时看不出来；一旦 mock 接入中性账单，预算“已用”会偏高，与真实后端不一致。

**建议**

在循环里补一个判断：

```ts
if ((tx.entryType ?? 'normal') !== 'normal') continue;
```
